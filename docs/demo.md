# 第 5 周演示手册

## 准备

在本机打开 `https://localhost:8444`，右上角选择演示身份。需要同时操作两个人时，使用普通窗口和 InPrivate 窗口以隔离 Cookie；两个普通标签共享同一个 Session。所有账号、联系方式与活动仅作虚拟演示。

| 身份 | 用途 |
| --- | --- |
| 林同学 | 发起人，发布和审核 |
| 陈同学 | 申请者，入组、请假、退出和反馈 |
| 周同学 / 许同学 | 第二申请者或旁观者，验证人数与群权限 |
| 待认证同学 | 验证发布/申请的身份门禁 |
| 平台管理员 | 治理、申诉、审计、统计 |

下面可分为两段展示：约几分钟的发布/组队/退出流程，以及开始后的签到、结束、反馈。不要为缩短等待直接修改数据库状态。

## A. 发布到重新组队

1. 林同学点击“发起一个行动”。例如“本周图书馆结伴自习”，容量3（含自己），公开地点“图书馆”；起止时间选择两位成员都没有活动冲突的未来时段。满足报名截止≤确认截止≤开始<结束，并留出足够申请审核时间。发布后人数为1。
2. 陈同学在发现页搜索标题，点击“看看这个计划”，填写留言并申请。申请显示待审核，人数仍为1。
3. 林同学在“我的行动”打开“审核申请 / 管理成员”，通过申请。人数变为2，出现“进入小组”。
4. 双方进入同一个小组；林同学设置置顶集合安排，陈同学发一条消息。页面约5秒刷新新消息，也可手动刷新。
5. 陈同学在确认截止前选择“请假（保留名额）”，人数仍为2。随后选择退出并填写理由，人数变回1，再访问原群被拒绝。
6. 陈同学重新申请，林同学再次通过；新申请 round=2，旧申请记录保留，同一活动继续使用原群。
7. 发起人可在开始前修改地点或时间，查看变更通知。时间与现有成员其他活动冲突时应看到明确失败，不能静默移除成员。

如时间充裕，可增加周同学申请来演示容量，或切为“待认证同学”验证身份门禁。最后名额的真正并发交错由自动化测试验证，连续手点不能冒充并发测试。

## B. 签到、结束与反馈

若希望当天连续演示，发布时可把开始时间设为当前时间后约10～15分钟，报名截止放在开始前数分钟；具体应预留完成 A 段的时间。活动开始后成员可自报签到，发起人选择结束；也可等待计划结束时间后的调度自动结束。

正常结束后，快照成员（含发起人）可以在24小时内填写完成状态、体验与同快照成员评分。部分完成/未完成需填写原因。提交成功后只能查看已有反馈，重复提交不会创建第二条。

初次初始化带有“读书分享会 · 已结束”示例，窗口从首次初始化对应的结束时间计算。当前烟测已使用陈同学的该活动反馈；可能显示“已提交”。这体现重复保护，不能当作一次新的现场提交。若已超时或想展示新提交，应新建短时活动并正常结束，不要清空或伪造已存在的反馈。

提前10分钟的待审提醒、提前30分钟的开始提醒仅适用于在该提醒时点之前已创建的活动；短时演示不会补发已经错过的提前提醒。精确时间边界已有测试证据。

## C. 举报、申诉和统计

1. 陈同学打开活动详情，举报此活动；使用“演示举报，无真实违规”等明确的虚拟理由与证据说明。
2. 切换平台管理员，进入“治理与统计”，按受理、开始处理、作出处置填写核验理由。课堂演示优先选“不予处置”，以免限制后续演示身份。
3. 陈同学到“举报与申诉”提出申诉，管理员完成复核。在审计中查看受理、处理、处置、申诉及复核记录。
4. 管理员打开运营统计并导出 CSV。说明取消活动进入到期分母，反馈/失约依据结束快照，零分母用空值而非假造0%。
5. 24h受理逾期告警使用自动化时间边界证据解释，不声称现场已经等待24小时。

演示结束后取消仍未进行的临时活动，或归档已结束/取消的活动。取消保留历史与审计，不需要删除业务表。发现页可能保留之前烟测活动，可用搜索/类型筛选；它们是实际执行留下的记录。

## 演示中可以准确说明的内容

可以说：Vue + Spring Boot + PostgreSQL 原型已运行，关键事务和异常路径有真实数据库验证，桌面/360px页面经过实际浏览器检查，站内通知与审计真实持久化。

需要同时说明：登录是虚拟身份切换，外部推送是模拟受理；校园认证、真实微信/短信、多浏览器矩阵、500VU/2000会话、备份恢复与月度可用性仍是后续任务。不要用单次页面快或测试数量代替性能指标。

## 常见情况

- 发布/批准冲突：换无冲突时段，或按业务规则退出/取消旧活动；不要改数据库绕过校验。
- 提示版本变化：刷新后按最新状态重新操作。
- 提示截止/确认/反馈已关闭：创建新的合适时段活动，已截止数据保留。
- 群已无权限：检查是否退出、被移除、账号受限或群已解散。
- 重启报进程已在运行：先使用 stop.ps1，再 start.ps1；不用按未知 PID 强杀。
- 后端启动失败：查看 .local 日志，检查 PostgreSQL、端口、证书路径和 settings.json；不要把初始化失败当成测试跳过。
