# 后续几周的优化与集成任务

按本轮范围约定，以下保留为后续工作。本轮不继续增加业务功能或生产部署复杂度。

| 工作 | 后续应交付的可检查结果 |
| --- | --- |
| 团队联调 | 冻结 API / 错误码 / DTO，完善 OpenAPI，与其他分支完成兼容和迁移验证；独立旧客户端契约测试 |
| 真实校内认证 | 确认校方协议/账号口径，实现 IdentityAdapter；校验 state/nonce、令牌签名/签发方/受众/有效期，增加真实退出联调 |
| 真实消息渠道 | 实现 PushAdapter；区分受理/送达/已读，核验渠道去重能力与99%/5分钟目标；注入发出后崩溃等场景 |
| 性能基线 | 20,000账号、500VU读写80/20、2,000在线会话；记录每接口P95、吞吐、失败率、机器资源和网络条件，检查读2s/写3s及首屏3s等指标 |
| 容量扩展 | 2倍数据/负载与实例扩展，保持业务代码不变，验证共享会话、锁、任务领取及资源容量 |
| 备份恢复 | 自动备份及保留规则；在隔离恢复库实际恢复，记录备份点/恢复点，验收RPO≤24h、RTO≤4h；不能仅以dump文件存在为通过 |
| 运维与安全 | 生产密钥/证书生命周期、迁移与运行账号分离、数据留存与擦除口径、日志/告警和月度探测99.5%证据；正式对外前禁用demo适配器 |
| 易用性与兼容 | 真正首次使用者的点击/耗时测试，80%首次发布≤3分钟、列表到申请≤5分钟；Chrome/Edge/Firefox/Safari及实际手机矩阵 |
| 工程整理 | 将原型Row DTO逐步类型化；完善新机初始化脚本，移除当前机器路径假设，建立不依赖初始读书会24小时窗口的浏览器烟测夹具，持续集成从干净环境真实执行现有测试 |

优先顺序建议为团队联调与真实适配器 → 性能/恢复/安全验收 → 用户试用和界面优化。每次改动按影响范围回归，保留失败原始证据；不能通过删除断言、跳过数据库测试、把未知状态当成功来获得绿色结果。

现有证据是本次环境与代码的快照，后续代码、数据库迁移或部署配置变化后，需要生成对应的新证据。未验证指标继续标记为未验证。
